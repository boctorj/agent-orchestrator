F-007-U-4 — coder fix-loop on ultrareview FAIL.

## What this change does
Extends the F-007 ultrareview gate so a FAIL verdict no longer escalates
immediately. The orchestrator now drives the coder through a fix-loop —
post the structured findings as a PR comment (so the human reviewing the
PR sees the meta-audit), invoke `address_review(source='ultrareview', ...)`
with a coder-prompt variant anchoring on "reviewer already endorsed, fix
without scope creep", wait for CI green, then re-run `/ultrareview` (not
the reviewer agent — endorsement already happened). The loop shares the
existing CAP_3 budget with tester-bug / reviewer-change / CI-fail fixes;
cap hit escalates with the unresolved findings in the message.

Surface changes:
- `address_review` accepts `source='ultrareview'` (in addition to the
  prior `tester` / `reviewer` / `ci` / `human` allow-list).
- `compose_fix_task` branches on `source=='ultrareview'` for the new
  prompt variant ("no scope creep, address ONLY the listed findings,
  the FEEDBACK above is the full source of truth — same shape as `ci`").
- New `_format_ultrareview_pr_comment` + `_run_ultrareview_once` helpers
  isolate the per-iteration verdict from the loop wrapping; the loop
  lives in the existing `_ultrareview_phase`.
- New `ultrareview_fix_cycle_N` event recorded per iteration (where N
  is the upcoming `review_round`) for cost attribution + cycle-log entries.
- `README.md` — added "Optional ultrareview gate (F-007)" subsection
  under "Human review as the merge gate".
- `CLAUDE.md` persona — extended the `address_review` and `cycle_review`
  bullets to document the new source and the FAIL fix-loop path.

## Decisions / deviations from the unit description

- **`source='ultrareview'` is opened on the public `address_review` MCP
  tool, not just internal.** The `cycle_review` automation drives it
  internally, but a human can also invoke `address_review(unit_id,
  'ultrareview', '<findings>')` manually after reading a FAIL escalation
  on a unit that hit cap-3 — same recovery shape as `source='ci'` / `'human'`.
- **`ultrareview_fix_cycle_N` event recorded BEFORE the `address_review`
  call**, with `N = review_round + 1`. Aligns with the `coder_resumed`
  cycle_number that `address_review` writes (which it increments first
  then records). The alternative was to record AFTER the call, but then
  N would correspond to "the cycle that just landed" which is more
  confusing in cycle-log reading order.
- **PR comment uses bulleted findings, not joined-blob.** GitHub markdown
  renders bullets as discrete items; a long blob of newline-joined
  finding strings reads as one wall of text.
- **The U-3 pinning test was updated, not added next to.** The U-3
  `test_flag_on_fails_escalates_with_findings` docstring explicitly
  flagged "initial impl; U-4 adds the fix-loop", so this PR rewrites it
  to assert the new behaviour rather than carrying both side-by-side.
  U-3's other 6 tests still pin the unchanged surfaces (PASS path, flag
  off, REVIEW_COMMENT skip, wrapper exception fail-closed, missing-PR-URL
  defensive, history breadcrumbs).
- **Did not modify `features/F-007/spec.md`.** U-3's "Approach" section
  already described U-4's behaviour accurately (FAIL loop with the new
  source + prompt variant, re-run ultrareview not reviewer); this PR
  ships the implementation rather than the spec.
