## What this change does
After our reviewer endorses via `REVIEW_RECOMMEND_MERGE`, `cycle_review` now branches on `feature.ultrareview_enabled`:

- **Flag off (default):** unchanged — terminate as `approved_awaiting_merge` (ntfy ready-to-merge).
- **Flag on + ultrareview PASS:** terminate as `approved_awaiting_merge` (ntfy ready-to-merge).
- **Flag on + ultrareview FAIL:** escalate with the findings list in the escalation message. The full FAIL fix-loop with `address_review(source='ultrareview', ...)` and cap-3 accounting ships in F-007-U-4.

Implementation:

- New `_ultrareview_phase(ctx)` helper sits alongside `_tester_phase` / `_copilot_phase` / `_reviewer_phase`. Calls `orchestrator.ultrareview.trigger` + `wait_for_result` from F-007-U-2.
- `_reviewer_phase` signature widened to return the final reviewer outcome string so `cycle_review` can fire the gate only on `REVIEW_RECOMMEND_MERGE` (per spec — `REVIEW_COMMENT` is a comment-only terminal, not an endorsement, so the gate is skipped).
- Wrapper exceptions are treated as a failed gate (fail-closed; matches `ultrareview._parse_bugs` direction). A missing CLI / parse error / other raise can never silently endorse a buggy PR.
- Events `ultrareview_started` / `ultrareview_passed` / `ultrareview_failed` land in `unit_events` for cost attribution + cycle-log entries (event names per the U-3 unit description).

## Tests
Five new tests in `TestCycleReviewUltrareviewGate` covering:

- flag off → ultrareview never fires
- flag on + PASS → `approved_awaiting_merge`, events recorded, PR URL passed to wrapper
- flag on + FAIL → escalation with findings, `ultrareview_failed` event carries findings in `details`
- `REVIEW_COMMENT` terminal → gate skipped even with flag on
- wrapper exception → fail-closed escalation, `ultrareview_failed` event still recorded
