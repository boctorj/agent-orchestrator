## What this change does

Phase 0 of the F-016 dispatcher/watcher split — makes the terminal-marker
recorder safe to re-apply to the same session response. Three pieces:

1. **`unit_events.dedupe_key` column + partial UNIQUE index.** Migration
   helper mirrors `_migrate_features_ultrareview` (PRAGMA-probe → ALTER
   → swallow duplicate-column race). `state.record_event` now accepts
   an optional `dedupe_key` kwarg and uses `INSERT OR IGNORE` —
   non-marker callers (NULL key) keep inserting one row per call.
2. **`orchestrator/markers.py`** — pure parser. `scan_response(role,
   text, *, allowed=None)` returns a `MarkerSpec` (or `None`). Same
   parser the lead recorder (today) and the watcher daemon (F-016-U-5)
   will both call; the determinism is what makes the dedupe key
   stable across both. `dedupe_key(...)` hashes
   `session_id|cycle_number|event_type|marker_payload`; the
   `cycle_number` field is load-bearing — same payload, different
   cycle must NOT collide.
3. **`scan_unit_session(unit_id, role)`** — new read-only MCP tool.
   Fetches `worker.tail_messages`, runs `scan_response`, returns the
   would-be marker without writing. Enables manual triage today and
   the daemon's reconciler tomorrow.

`_record_terminal_marker` in `tools/execution.py` is refactored to
delegate parsing to `markers.scan_response` and pass the dedupe key
through. Zero behaviour change for current users: all 2006 pre-existing
tests pass unmodified, plus 51 new tests in
`tests/test_markers.py` / `tests/test_f016_u1_idempotent_marker_recording.py`
/ `tests/test_state.py::TestEventDedupeKey` + `TestUnitEventsDedupeKeyMigration`.

Also consolidated marker regex constants — `orchestrator.tools.__init__`
now re-exports them from `markers.py` (single source of truth, no drift).

## Decisions / deviations from the unit description

- **Regex single-source-of-truth.** While moving the parsing rules
  into `markers.py`, the marker regex constants got two homes (the
  legacy `orchestrator.tools.__init__` re-exports, and `markers.py`).
  Made `tools.__init__` re-export from `markers.py` to prevent drift
  rather than maintaining two parallel definitions. Adjacent cleanup,
  but contained — the public legacy import surface is preserved.
- **`MarkerSpec` carries `payload` + `extras` separately.** `payload`
  is the deterministic dedupe-hash input; `extras` is the variable
  per-marker MCP-return payload (e.g. `pr_number`, `bug`, `reason`).
  Keeping them split means the daemon (F-016-U-5) can recompute the
  dedupe key without needing the MCP-formatting shape.
