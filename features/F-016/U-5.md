## What this change does

Adds `orchestrator/daemon.py` — a level-triggered reconciliation daemon
that calls F-014's pure `decide_transitions` engine each tick and
executes the resulting actions idempotently. Stateless between ticks
(Kubernetes-controller pattern); singleton-per-workspace via a new
`daemon_locks` SQLite table; CAS-guarded against lead/daemon double-
writes via the existing `work_units.owner` column from F-016-U-4.
Opt-in via `ORCH_DAEMON_DRIVE=true` — without the env var, `run_daemon`
is a no-op so accidental launches don't take over a workspace.

The daemon walks `state.list_active_units()` each tick and for each row:

1. **Observe** — tails coder/tester/reviewer worker sessions, runs the
   pure `markers.scan_response` parser, records new markers with the
   Phase 0 `dedupe_key` so duplicate scans are no-ops.
2. **Apply marker transition** — CAS-claims `owner='daemon'`, re-reads
   inside the claim (cancellation + status guards), flips status (and
   `last_error` for BLOCKED) via `state.touch_unit`, releases.
3. **F-014 engine** — when the unit has a PR, runs `_probe_and_decide`
   and applies each action via the existing `tools.health._apply_action`
   helper. No parallel state machine — one engine, two callers (lead +
   daemon).

Short-circuits checked between every stage: `cancelled_at` (Phase 2.5
sticky cancel), terminal status, and `has_active_advance_lock` (the
lead's ~1s `send_to_unit_async` submit window).

Singleton enforcement (spec § "SQLite-backed, not pidfile"): the
`daemon_locks` row is keyed by the absolute `state.db` path. Heartbeat
takeover after 30s (`DEFAULT_DAEMON_LOCK_STALE_AFTER_S`) makes crash
recovery automatic — startup just runs `tick`; the spec's "no special
recovery path" falls out of the level-triggered design.

CLI: `orchestrator daemon start` (foreground loop) and
`orchestrator daemon status` (read-only lock-row snapshot). The
proposal's `daemon stop` / `daemon logs` are out of scope here —
SIGTERM cleans up; logs go to stderr. They can ship in F-016-U-7
cleanup if needed.

## Manual verification needed

## Decisions/deviations from the unit description

- **`Action` dataclass not extended** — BLOCKED's status flip carries
  `last_error` in `MarkerSpec.last_error` and the daemon's
  `_apply_marker_transition` passes it directly to `touch_unit`. Adding
  a fourth Action kind for "transition with error" would touch the
  F-014 surface for one caller; deferred to F-016-U-7 if the pattern
  recurs.
- **Status not re-checked inside `_apply_health_action`** — F-014
  actions are generated from a snapshot inside `_probe_and_decide_unit`;
  if the status changes between probe and apply, the F-014 helper's
  internal status checks (in `_merge_transitions` et al.) already
  preconditioned on the snapshotted status. Matches the existing
  `inspect_unit_health` race window — re-using rather than
  re-engineering.
- **Coverage 91% on `daemon.py`** — uncovered lines are defensive
  `latest is None` post-CAS branches and the signal-handler restore
  on platforms without SIGINT. Both are intentional defense; tests
  that mock them out would be testing the mocks.
