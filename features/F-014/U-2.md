## What this change does

Wires F-014-U-1's pure probe + decision table into MCP as the new
canonical `inspect_unit_health(unit_id, dry_run=False)` tool, and
re-frames `check_unit_pr` / `reconcile_unit_pr` as deprecated aliases.

On non-dry-run, `inspect_unit_health`:
- runs `probe_unit_health` against a production GH client (wrapping the
  existing `github.get_pr_state` / `get_pr_check_runs`) and a production
  Anthropic client (wrapping `ManagedAgentWorker.client.beta.sessions.retrieve`);
- runs `decide_transitions`, applying each `actions_to_apply` via the
  existing `state.touch_unit` / `state.record_event` primitives (reuse,
  not duplicate);
- persists every `ShadowDecision` as a `shadow_transition_proposed`
  event with the full structured payload (`rule_name`,
  `predicted_action`, `trigger_inputs`, `rationale`) in `details`;
- at most once per `ORCH_HEALTH_SNAPSHOT_INTERVAL_HOURS` (default 24h)
  per unit, persists the serialised `HealthReport` as a
  `health_report_snapshot` event for forensics retention. Setting the
  env var to `0` disables snapshot retention; garbage values fall back
  to the 24h default.

Returns a markdown digest with the HealthReport summary, applied
actions, and shadow decisions so the lead sees what was applied and
what was deferred.

`check_unit_pr` and `reconcile_unit_pr` remain registered as MCP tools,
keep their legacy JSON shape unchanged, preserve `reconcile_unit_pr`'s
cycle-log writer side effect on merged polls, and log a deprecation
warning on every call.

CLAUDE.md is updated to surface `inspect_unit_health` as the canonical
recommendation in the per-unit flow, the multi-feature scheduling rule
(step 8), the restart-recovery flow, and `tail_worker`'s `idle` branch
guidance; existing `reconcile_unit_pr` / `check_unit_pr` references are
preserved alongside the canonical guidance.

## Decisions/deviations from the unit description

- **Snapshot env var.** The spec leaves the env var name + default TTL
  open. Picked `ORCH_HEALTH_SNAPSHOT_INTERVAL_HOURS` with a default of
  `24` so the default behaviour matches the spec's \"first probe per
  unit per UTC day\" phrasing; `0` disables. Documented in the
  `inspect_unit_health` docstring + CLAUDE.md.

- **Production GH client coverage.** The probe protocol has 11
  methods; today's `orchestrator.github` only directly supports
  `get_pr_state` and `get_pr_check_runs`. The production client wires
  those two and returns safe defaults for the richer probes (review
  threads, codeowner reviewers, required-checks delta, branch-compare,
  Copilot review, head commit age, force-push timestamp, merge-commit
  reachability). The decision table's `no data → no signal` branches
  handle the absence cleanly. Widening these to real GH probes is
  scoped to F-015 / F-016 when the daemon needs them.

- **Aliases stay live.** \"Thin alias\" is read as \"behaviour-preserving
  + deprecation-marked\" rather than \"re-implemented through
  `inspect_unit_health` under the hood\". The existing aliases' code
  paths satisfy every legacy test (the
  `test_reconcile_delegates_to_check_unit_pr` contract in particular
  requires `reconcile_unit_pr` to call `check_unit_pr`), and the
  deprecation warning is the chat-visible migration signal.

- **`check_unit_pr` (dry-run alias) does not snapshot or record shadow
  events.** The spec scopes \"applies actions / writes shadow events /
  writes snapshot\" to non-dry-run, which matches the existing
  `check_unit_pr` zero-events contract pinned by
  `test_check_unit_pr_records_zero_events_across_every_pr_state`.
