## What this change does

Adds `orchestrator/health.py` — two pure functions backing the upcoming
`inspect_unit_health` MCP tool (parent feature F-014):

- **`probe_unit_health(unit_id, gh_client, anthropic_client, *, local_state, ...)`** —
  assembles a `HealthReport` from data pulled via two injected clients. No
  network, shell, or DB I/O of its own; every external call routes through
  the clients, every local fact is passed in. Snapshot covers:
  - PR: state, mergeable, mergeable_state, conflict file list, head_sha,
    merge_commit_sha
  - Git: commits ahead/behind base, head_sha + age, last force-push timestamp
  - CI: all check_runs with name/status/conclusion/details_url (failing-job
    log URLs preserved); required-vs-actual delta; pending vs failing split
  - Reviews: approvals, changes-requested, dismissed, unresolved-thread
    count (excluding outdated), codeowner-requested reviewers
    (users + `team:` prefixed teams), copilot presence + state
  - Worker sessions: per-role `(idle|running|terminated)` from Anthropic
  - Orchestrator: cycle vs cap-3 (proximity), last_activity age, downstream-blocked

- **`decide_transitions(local_state, report) -> Decision`** — pure decision
  table. Returns two buckets:
  - `actions_to_apply` covers the three existing reconcile cells from
    `ops.reconcile_unit_pr` (`merged + in_ci → done` + merged event;
    `merged + approved_awaiting_merge → done` + merged event;
    `merged + escalated → done` + clear `last_error` + merged + recovered
    events), the cycle-log writer side effect on a populated
    `merge_commit_sha`, the active-role merge-refusal branch, and three
    new event-only signals: `pr_conflict_detected` (with file list),
    `required_check_missing`, `ci_drift_detected` (sets `last_error`,
    no status change).
  - `shadow_decisions` covers `escalated_to_in_ci_reset` (CI green +
    approved + no open threads), `merge_reverted_flag` (done +
    `merge_commit_sha` no longer reachable from main), and a third
    risky cell identified during implementation:
    `dead_worker_during_active_status` (active status paired with a
    terminated Anthropic session). Each carries `rule_name`,
    `predicted_action`, structured `trigger_inputs`, and a `rationale`.

Tests (`tests/test_health.py`, 65 tests) exercise every public function
plus a `(status x pr_state x ci x reviews x conflicts)` parametrized
table for both `actions_to_apply` and `shadow_decisions`. No new
dependencies.

## Decisions / deviations

- **`local_state` is a keyword-only argument to `probe_unit_health`**
  even though the unit description lists the signature as
  `(unit_id, gh_client, anthropic_client)`. The orchestrator-section
  data (cycle count, `last_activity` age, `downstream_blocked`) has to
  come from somewhere local, and threading it through one of the
  clients would conflate "external I/O source" with "local context".
  Keyword-only keeps the call site explicit at production sites while
  the test fakes don't have to fabricate a client that knows about
  state.db. `cycle_cap` and `now` are similarly keyword-only for
  testability.
- **Added a third shadow rule (`dead_worker_during_active_status`)**
  beyond the two named in the unit description. The unit text invites
  this ("any additional risky cells we identify during implementation");
  the rule captures the active-status-paired-with-terminated-session
  case that today's restart-recovery flow only triages manually.
- **`Action` is a single dataclass with a `kind` discriminator** rather
  than a sealed hierarchy of `TransitionAction` / `EventAction` /
  `SideEffectAction`. Frozen dataclass + discriminator pattern matches
  this codebase's existing `BlockedPayload` / `VerificationResult`
  approach and keeps tests' attribute-equality checks straightforward.
- **`merge_commit_on_main` lives on `HealthReport`** (default `True`)
  rather than being read mid-`decide_transitions`. Keeps
  `decide_transitions` free of any client reference — required for the
  "pure decision table" contract.
- **`features/F-014/spec.md` in the repo describes a different scope**
  (role-prompt decomposition) than the unit task message I was given
  (health probe + decision table). Followed the unit task message as
  the source of truth, since that's what spawned this work. Worth
  flagging to the human in case the spec on disk needs updating.
