# F-017: Tighten cycle log format + split prompt-injection from full audit

## Intent
Cycle logs (`features/F-XXX/U-N.md`) are auto-generated by the orchestrator at terminal state per F-006. They serve three consumers with different needs: (1) downstream **worker prompts** — injected as `## PREDECESSOR UNITS` context blocks via `compose_*_task` → `_render_context_blocks` in `orchestrator/tools/__init__.py`; (2) the **lead** via `feature_memory(F-X)`; (3) **human audit** on disk + GitHub.

Today every consumer pays the cost of the same ~120-line file. The dominant cost is consumer (1): a unit with 3 predecessors injects ~12K tokens per worker spawn, paid 3-9× per cycle. Most of that content (cycle-history boilerplate, full review-thread snippets, manual-verification notes, quality-gates output) is audit-only and unusable for the worker reasoning about the predecessor's contract.

This feature **splits prompt-injection from full audit** without changing storage:

1. Introduce a **TL;DR section** at the top of every cycle log, capped to ~30 lines: what shipped, downstream contract (data types, invariants, side effects), key decisions worth knowing. Hand-curatable by the coder at PR-write time; orchestrator auto-fills from PR sections by convention.
2. Add `cycle_log_summary(unit_id)` returning JUST the TL;DR portion. The existing `read_cycle_log(unit_id)` continues to return the full file.
3. Switch `_render_context_blocks` to inject the **summary** (not the full log) as predecessor context. Token cost per predecessor drops ~75% without losing audit value (the full record stays on disk; the canonical full audit lives on GitHub via `gh pr view`).
4. `feature_memory` and human audit continue to read the full file.

Existing cycle logs are not back-filled — they remain immutable per F-006. Only new cycle logs ship in the new format. Workers reading old-format predecessors fall back to the full file (with a one-time deprecation note in the orchestrator log).

Defers to F-016 Phase 3: the orchestrator-as-sole-writer + auto-commit-on-terminal policy. That's a daemon concern; this feature is about content shape, not who writes.

## Acceptance

When both units merge:
1. `cycle_log_summary(unit_id)` exists, returns the TL;DR section as
   plain markdown (heading-stripped, ≤30 lines), and is pinned by tests.
2. `read_cycle_log(unit_id)` continues to return the full file
   unchanged (no regression for the lead's `feature_memory` digest or
   human audit).
3. New cycle logs written by the orchestrator contain a `## TL;DR`
   section as the first section after the front matter. The section
   has three required sub-headings (`### What shipped`, `### Downstream
   contract`, `### Decisions worth knowing`) — even when empty, the
   sub-headings are present so the format is grep-stable.
4. `_render_context_blocks` injects the summary (not the full log) for
   predecessor units when a TL;DR section is present. Logs without a
   TL;DR section fall back to the full body (one-time orchestrator
   stderr log per unit).
5. A token-count test confirms that a 3-predecessor task composed from
   the new format is ≥60% smaller in the `## PREDECESSOR UNITS` block
   than the equivalent composed from full-body logs.
6. Existing cycle logs on disk are NOT modified by this feature (F-006
   immutability invariant preserved).

## Out of scope

- Back-filling existing cycle logs with TL;DR sections — they remain
  immutable per F-006. Workers reading old-format predecessors get the
  full body via the fallback.
- Changing what `feature_memory(F-X)` returns to the lead — it
  continues to read the full file. If the lead's digest should also
  switch to the summary, that's a separate decision.
- Auto-commit / daemon-ownership of cycle log writes — that's F-016
  Phase 3.
- Pruning the cycle history / review-threads sections from the full
  file. The full body remains the canonical audit; the summary is a
  derived view layered on top.

## Approach

**Writer side (U-1):**
- Extend the cycle-log template to emit a `## TL;DR` section between
  the front matter and the existing "Coder's PR description" section.
- Auto-fill the TL;DR from conventionally-named sub-sections in the
  coder's PR body (`### What shipped`, `### Downstream contract`,
  `### Decisions worth knowing`). If absent, the section is emitted
  with the three sub-headings empty plus a `_TBD — coder did not fill
  in TL;DR; full body below._` placeholder under each.
- Update [`orchestrator/prompts/coder.md`](../../orchestrator/prompts/coder.md)
  to instruct coders to fill in the three sub-sections in their PR
  body (additive to the existing "Spec satisfaction" + "Decisions /
  deviations" template).

**Extractor side (U-1):**
- New function `cycle_log_summary(unit_id) -> str` in
  [`orchestrator/cycle_log.py`](../../orchestrator/cycle_log.py).
- Implementation: read the full file, find the `## TL;DR` heading,
  return everything from that heading down to (but not including)
  the next `## ` heading. Strip the wrapping heading itself.
- Return empty string when the section is absent — caller decides
  whether to fall back.

**Injection side (U-2):**
- In `_render_context_blocks` (`orchestrator/tools/__init__.py`),
  change the call from `read_cycle_log(predecessor_id)` to
  `cycle_log_summary(predecessor_id) or read_cycle_log(predecessor_id)`.
- Emit a single stderr log line per predecessor on fallback so the
  format-migration cost is observable.

## Constraints

- **F-006 immutability preserved.** Existing cycle logs are read-only;
  this feature only adds capability for new logs.
- **Backward compatible.** Logs without TL;DR continue to work via
  fallback. No format-version bump required.
- **Deterministic.** Both `cycle_log_summary` and the writer's
  TL;DR-extraction logic must be deterministic on the same input.
- **No new dependencies.** Implementation is plain Python + markdown
  parsing (regex on `## TL;DR` heading).
