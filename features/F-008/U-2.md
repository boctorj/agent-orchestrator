## What this change does
Adds `tail_worker(unit_id, role, limit=20)` to `orchestrator/tools/ops.py`.
It resolves the unit's persisted session id for the requested role,
calls `make_worker(role).tail_messages(sid, limit=limit)`, and renders
the result with status-aware framing:

- `running`    → `worker active, last N messages` + messages
- `idle`       → `worker completed, final messages` + messages
- `terminated` → `worker dead (reason); last messages before death` + messages
- `not_found`  → `no session for unit_id/role — likely never spawned`

Read-only — no state.db writes, no events, no session perturbation.
Backend-aware via `make_worker(role)` so it works on both
`managed_agents` and `docker` (subject to F-008-U-1's documented
docker `running` limitation).

## Decisions / deviations
- Used `make_worker(role)` rather than the `ManagedAgentWorker` that
  `resume_unit` directly constructs, because the F-008 spec requires
  both backends. `resume_unit`'s direct-construction predates the
  worker factory; consolidating it is out of scope for U-2.
- Introduced a module-level `_ROLE_TO_SESSION_ATTR` mapping for
  `tail_worker`'s role→attr lookup. Not refactored into
  `resume_unit` (separate concern, separate PR).
- Tool returns plain text (status-aware framing) rather than JSON,
  matching the spec's chat-friendly intent.
- Default `limit=20` at the MCP layer per the F-008 spec's
  ergonomic-floor vs technical-ceiling split; backend still accepts
  higher values for power-callers.
