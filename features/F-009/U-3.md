## What this change does

`spawn_tester` and `spawn_reviewer` are now idempotent on units that already have a `{role}_session_id`. Pre-F-009-U-3, both refused with `ERROR: ... already exists`, blocking legitimate recovery — the worker backend still held accumulated context (PR diff, prior findings, test scaffolding) but no surface could re-engage it. Spawning fresh would discard the context and re-pay clone+inventory cost.

New contract: when the unit has a prior `{role}_session_id`, the existing worker session is resumed via `build_recovery_prompt(role, reason)` instead of being refused. The reason is derived from unit status:
- `'escalated'` → `post-escalation` (interpolates `last_error`)
- any active status → `transient-retry`

The marker chain (`_record_terminal_marker`, shipped in F-009-U-1) runs identically regardless of which branch ran — status flips per marker, events recorded the same way.

Both spawn surfaces converge on the same response shape (`_format_tester_marker_response` / `_format_reviewer_marker_response`) so callers (`cycle_review`'s `_record_step`, the MCP tool's JSON return contract) don't need to special-case the resume path.

### `address_review` — already correct, now documented

`address_review` already supported recovery on escalated units (the `coder_session_id` is the source of truth, not status). The docstring now states this contract explicitly and a regression test (`TestAddressReviewOnEscalatedUnit`) pins the behaviour. No code change to the function body — no guard ever rejected an escalated unit.

### Recovery prompts — single source of truth

`build_recovery_prompt(role, reason, *, last_error, details)` returns the canonical stock message for each `(role, reason)` pair (3 reasons × 3 roles = 9 templates). Each template names the role's marker vocabulary so the resumed agent knows exactly what to emit. Unknown pairs raise `ValueError` so prompt drift is loud rather than silent.

The legacy literal `_TESTER_RESUME_RECOVERY_PROMPT` in `_resume_or_spawn_tester` (F-013-U-1) now calls through `build_recovery_prompt("tester", "transient-retry")` to avoid drift between the two paths.

## Decisions / deviations from the unit description

- **`_resume_or_spawn_tester` (F-013-U-1) kept intact** rather than replaced with a delegating shim. The F-013-U-1 test suite asserts that `spawn_tester` is *not* called when the session is set (it monkeypatches `spawn_tester` to `boom`), so a pure delegate would break those tests. The helper now uses `build_recovery_prompt` so the prompt content is canonical. A follow-up could consolidate this further; out of scope here.
- **`spawn_tester`'s BLOCKED return remains a bare `"BLOCKED — ..."` string** (matching the pre-existing contract for consumers of the public MCP tool). `_resume_or_spawn_tester`'s JSON-on-BLOCKED contract is retained for the `_tester_phase` / `_record_step` integration that needs `outcome="BLOCKED"` to short-circuit cleanly.
- **`_resume_role_for_recovery` clears `last_error` on entry** via `touch_unit(..., clear_error=True)`. This mirrors `reconcile_unit_pr`'s pattern when transitioning escalated → done. If the worker re-emits BLOCKED, `_record_terminal_marker` repopulates the new error.
- **Recovery prompt for tester transient-retry is byte-identical to the previous `_TESTER_RESUME_RECOVERY_PROMPT` literal** to keep all F-013-U-1 contract assertions ("network timeout" / "do not redo" / marker names) passing without changes.
