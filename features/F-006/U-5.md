## What this change does

Lands the proposal §5 *Feature memory bootstrap* surface — a new
`feature_memory(feature_id)` MCP tool that returns a single markdown
blob the lead reads at session start to re-orient without scrolling
chat history. The tool delegates to a pure library function
(`orchestrator/feature_memory.py`) that splices together:

- `features/<feature_id>/spec.md` contents
- `git log -10 -- features/<feature_id>/spec.md` (the decision timeline)
- per-unit `unit_summary` digest (status, cycles, last error, terminal-marker counts)
- cycle-log "Final" sections (PR + last cycle subsection) for each unit with a log on disk
- recent escalation events across the feature (newest first, capped at 10)

Read-side is fully null-safe: missing `features/` directory, missing
`spec.md`, a non-git workdir, or a half-written cycle log each degrade
to a placeholder rather than raising — matching the unit description's
"Read-side must handle missing features/ directory gracefully" clause
and the best-effort discipline established by `cycle_log.py`'s writer.

## Manual verification needed

None beyond CI — the new tool is read-only, has no mutation side effects,
and is fully covered by the new test file (88% line coverage on
`feature_memory.py`, 91% repo-wide).

## Decisions / deviations from the unit description

- **Reused `blocked_hints.extract_reason_from_details`** for parsing
  structured BLOCKED `details` blobs instead of re-implementing JSON
  decoding — keeps the two surfaces in sync.
- **Cycle-log "Final" interpretation:** the proposal text reads "cycle
  log 'Final' sections (~500 tokens per merged unit)". I read the on-disk
  log and extract the `## PR` block (capturing the post-merge SHA backfill,
  the one allowed post-finalization edit) plus the cap-3 summary line and
  the last `### Cycle N — heading` subsection. That gives the lead the
  outcome plus the terminal cycle's heading without dumping the whole log.
- **Read from disk, don't re-render.** The proposal's writer in
  `cycle_log.py` writes the authoritative artifact; reading what's on
  disk picks up post-merge SHA amendments transparently. Units still
  in-flight (no log yet) are silently skipped in the "Cycle log finals"
  section — the "Units" digest above already calls out their status.
- **Retired the U-1-era `test_no_feature_memory_mcp_tool_registered_yet`
  guard** in `tests/test_f006_u1_spec.py`. U-5's job is exactly to land
  the tool, so the negative assertion is now stale; left the surrounding
  `test_compose_task_templates_do_not_inject_spec_content_yet` guard
  intact since that wiring is U-4's, not U-5's.
